ABSTRACT

The ToxicGuard AI system is an intelligent, web-based multi-label comment moderation platform developed to assist online community administrators, discussion forums, and collaborative platforms in detecting, categorizing, and moderating toxic user-generated content. As digital communication expands exponentially, manual moderation has become infeasible due to severe personnel costs, psychological fatigue, and high latency. Furthermore, conventional keyword blocklists fail against obfuscated text, slang, and intentional misspelling, while large generative language models present prohibitive computational overhead and latency. ToxicGuard AI addresses these challenges by combining a slang-normalized Natural Language Processing (NLP) pipeline with high-throughput Deep Learning architectures in a clean, responsive web interface.

Users and moderators can authenticate securely, interact with a real-time social feed, test arbitrary sentences via an interactive Live Toxicity Analyzer, and monitor content across six distinct toxicity dimensions: Toxic, Severe Toxic, Obscene, Threat, Insult, and Identity Hate. The application integrates an automated three-tier moderation policy that instantly approves benign comments (probability < 0.40), routes borderline content (0.40 ≤ probability < 0.75) to a human-in-the-loop administrative queue for review, and automatically blocks high-severity infractions (probability ≥ 0.75). Furthermore, an administrative telemetry module provides historical 14-day volume trends, class distributions, and token frequency metrics.

The application follows the Model–View–Controller (MVC) pattern, utilizing an asynchronous FastAPI backend in Python, SQLite with SQLAlchemy ORM for portable and robust persistence, and a modern React 19 single-page application styled with Tailwind CSS for the front end. By mitigating class imbalance through weighted binary cross-entropy loss, the system delivers sub-40ms CPU inference latency while maintaining high sensitivity to critical threats. The project demonstrates how artificial intelligence and modern web frameworks can be integrated to foster safer online discourse while remaining lightweight, maintainable, and extensible.

CHAPTER 1.
INTRODUCTION

1. Identification of Client/ Need/ Relevant Contemporary issue

Client: The primary clients for the ToxicGuard AI platform are online forum moderators, social media platform administrators, academic discussion boards, gaming communities, and collaborative web platforms that require automated, fair, and contextual content moderation. Secondary stakeholders include end users seeking healthy, constructive online spaces free from cyberbullying and harassment.

Need: Relying exclusively on human moderation teams induces substantial financial expense, psychological strain, and unacceptable latency when identifying critical infractions such as violent threats. Conversely, basic keyword filtering is easily bypassed by internet acronyms, intentional phonetic misspellings, and leetspeak. There is a pressing need for a unified, responsive platform that accurately detects multi-label toxicity in real time, routes borderline comments to human moderators, and provides transparent telemetry analytics.

Relevant Contemporary Issue: Proliferation of hate speech, toxic comments, and online harassment has emerged as a significant societal challenge impacting digital well-being. Modern natural language processing [1] and deep learning classifiers allow applications to understand contextual nuances and classify multi-label text efficiently. ToxicGuard AI responds to this critical issue by integrating an asynchronous FastAPI backend [1], a normalized SQLite database [2], and deep neural networks [3] into an extensible moderation assistant.

2. Identification of Problem

Three primary problems motivate the project. Obfuscation and slang: users frequently circumvent static blocklists using colloquial abbreviations and character substitutions. Severe class imbalance: critical hostility categories such as violent threats appear in fewer than 1% of training samples, causing standard neural models to collapse into zero predictions. Tool fragmentation: existing text classification models often exist as isolated research scripts without integration into production REST APIs, human-in-the-loop review dashboards, or real-time web interfaces.

The problem statement is: how can a lightweight, multi-label Deep Learning web application detect toxic content in real time, route borderline comments to human administrators, and provide telemetry analytics within a responsive full-stack platform?

3. Identification of Tasks

The project involves the following interrelated tasks: (1) Requirement gathering and analysis; (2) System design using MVC; (3) Frontend development (React 19 & Tailwind CSS); (4) Asynchronous backend development (FastAPI & JWT); (5) NLP slang normalizer and deep learning sequence model integration; (6) SQLite database schema creation and seeding; (7) Automated testing, profiling, and final report documentation.

CHAPTER 4.
RESULTS ANALYSIS AND VALIDATION

1. Implementation of solution

1.1. Development environment and project structure

The application was implemented using the FastAPI asynchronous web framework in Python [1], following the MVC architectural pattern. The front end uses React 19 and Tailwind CSS [5], the persistence layer uses SQLite [2] with SQLAlchemy ORM, and the AI features use PyTorch and Keras [3] with Python [4] as the primary implementation language. The source code is organized into modular directories: backend/, frontend/, models/, and docs/ [6]. All pages share a consistent dark-slate aesthetic, top navigation bar, real-time status badges, and interactive controls.

1.2. NLP Text Preprocessing and Slang Normalization Pipeline

Raw user text undergoes four deterministic transformations before feature extraction: (1) Sanitization: Regex stripping of HTML tags, URLs (http\S+|www\S+), and repetitive character elongations ("soooo goooood" → "soo good"); (2) Slang Expansion: Normalization of 50+ toxic internet acronyms via dictionary lookup ("wtf" → "what the fuck", "kys" → "kill yourself", "stfu" → "shut the fuck up"); (3) Negation-Preserving Stopword Filter: Stripping extraneous words while preserving critical negation tokens ("not", "never", "no", "without") to avoid sentiment inversion; (4) Tokenization & Sequence Padding: WordNet lemmatization and sequence padding to fixed length L = 50.

1.3. Deep Learning Multi-Label Model Architectures

Unlike single-label Softmax models where probabilities sum to 1, multi-label toxicity modeling treats each category as an independent binary event via 6 Sigmoid activation units. The production Hybrid CNN + BiLSTM architecture operates as follows:

E = Embedding(X) ∈ ℜN × 50 × 64  •  C = ReLU(Conv1D(E)) ∈ ℜN × 48 × 64  •  Ht = [ h⃗t  ‖  h⃖t ] ∈ ℜ64
σ(zk) = 1 / (1 + e−zk),   k ∈ {1, 2, ..., 6}

1.4. Class Imbalance Mitigation and Loss Function Engineering

To prevent model collapse on rare minority classes (*Threat* < 1%, *Identity Hate* < 1.5%), we implement Weighted Binary Cross-Entropy Loss, assigning higher penalties to false negatives on severe violations:

ℒ = − (1/N) ∑i=1..N ∑k=1..6 [ wk yik log(pik) + (1 − yik) log(1 − pik) ]   where   wk = Nnegative, k / Npositive, k

1.5. Three-Tier Automated Moderation Policy Engine

The backend evaluates the maximum predicted probability Pmax = maxk(pk): (1) Approved: Pmax < 0.40 → published immediately with a green Approved badge; (2) Flagged: 0.40 ≤ Pmax < 0.75 → rendered with an "Under Review" banner and sent to the Admin Queue; (3) Blocked: Pmax ≥ 0.75 (or Threat ≥ 0.50) → hidden from the public feed and logged as an infraction.

2.2. Observations & 3. Limitations of the current implementation

SQLite is suitable for single-node development but requires migration to PostgreSQL for distributed enterprise scale.

CHAPTER 5.
CONCLUSION AND FUTURE WORK

1. Conclusion

The ToxicGuard AI capstone project successfully conceptualized, engineered, and validated an integrated multi-label toxic comment moderation system combining NLP text normalization, deep learning sequence modeling, high-throughput asynchronous REST APIs, and responsive telemetry analytics. By unifying FastAPI, SQLite, and a production Hybrid CNN + BiLSTM network, the platform provides real-time multi-label classification across six hostility dimensions, an algorithmic slang-expansion NLP pipeline, a deterministic three-tier moderation policy, an administrative review queue, and interactive telemetry analytics in one lightweight and scalable application. The output screens and empirical evaluations demonstrate that all project objectives were fully achieved with a 100% test pass rate and sub-40ms inference latency.

2. Future work

  • Transformer fine-tuning: integrate quantized DistilBERT or RoBERTa models to capture deeper bidirectional attention and long-range semantic dependencies.
  • Multilingual and code-mixed moderation: expand the NLP preprocessor and tokenizers to handle multilingual discourse, including Hindi and Hinglish.
  • Conversational context analysis: evaluate multi-turn conversation threads rather than isolated comments to detect subtle sarcasm and passive-aggressive hostility.
  • Dynamic user reputation scoring: implement Bayesian trust scoring to dynamically adjust moderation thresholds based on past user behavior.
  • Cloud integration and containerization: package the services into Docker containers deployed on AWS or Google Cloud with PostgreSQL for enterprise horizontal scalability.
  • Active learning feedback loop: automatically incorporate administrator override decisions to iteratively retrain and adapt model weights over time.
