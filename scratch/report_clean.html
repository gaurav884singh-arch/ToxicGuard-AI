ABSTRACT

In contemporary digital discourse, user-generated content across online forums and social platforms has grown exponentially, bringing severe challenges in hate speech, obscenity, and violent threats. Manual moderation cannot scale, while naive keyword blocklists fail against internet slang and character masking. This capstone project develops ToxicGuard AI, an end-to-end multi-disciplinary platform unifying Natural Language Processing (NLP), Deep Learning (DL), Full-Stack Web Engineering, and Data Analytics. We formulate toxicity detection as a multi-label classification problem across six canonical classes: Toxic, Severe Toxic, Obscene, Threat, Insult, and Identity Hate. The system implements a slang-normalization NLP pipeline, benchmarks six ML/DL architectures, mitigates class imbalance via weighted binary cross-entropy, and integrates a production Hybrid CNN + BiLSTM model into an asynchronous FastAPI backend and React 19 frontend with 100% test pass rate and sub-100ms inference.

Chapter 1.
INTRODUCTION

1.1 Identification of Client/ Need/ Relevant Contemporary issue

Client:

Stakeholders include social media platforms, university discussion forums, academic LMS portals, gaming chatrooms, collaborative wikis, and community managers requiring automated moderation without arbitrary censorship.

Need:

Relying exclusively on human moderation teams induces substantial personnel costs, psychological fatigue, and unacceptable latency in removing high-severity infractions (e.g., violent death threats). Conventional regex solutions fail on slang. An intelligent, contextual, multi-label classification system is needed to categorize content along nuanced severity dimensions, filtering danger while routing borderline expressions to human reviewers.

Relevant Contemporary Issue:

The contemporary challenge resides at the intersection of automated natural language understanding, digital safety, and algorithmic fairness. Aggressive false positives stifle constructive free speech, whereas false negatives allow toxic hostility to proliferate. By grounding moderation policies in a multi-label deep learning framework with calibrated probability thresholds, human-in-the-loop governance, and telemetry, this project provides a balanced, ethically grounded solution.

1.2 Identification of Problem

The development of ToxicGuard AI addresses five technical bottlenecks in moderation ecosystems:

  1. Obfuscated Feeds: Commentators circumvent word filters via phonetic substitutions (f***, a$$hole), slang (wtf, stfu, kys), and character elongation (loooool).
  2. Binary Oversimplification: Rigid "safe vs. unsafe" binaries fail to separate colloquial vulgarity from severe actionable threats.
  3. Severe Class Imbalance: High-severity classes like Threat represent <1% of samples, causing standard neural networks to collapse into all-negative predictions.
  4. Inference Latency Bottlenecks: Heavy transformer pipelines often introduce 300ms–800ms CPU latency per item, creating unacceptable lag in real-time feeds.
  5. Architectural Isolation: Academic classifiers frequently lack integration with production REST APIs, secure JWT authorization, persistence databases, and administrative oversight.

1.3 Identification of Tasks

To systematically address these challenges, the project was organized into five engineering phases: (1) Dataset Ingestion, EDA & Class Imbalance Profiling; (2) Algorithmic NLP Preprocessing Pipeline; (3) Multi-Model Deep Learning Benchmarking & Weighted Loss Optimization; (4) Asynchronous FastAPI Backend with JWT & SQLite; and (5) React 19 Frontend with Recharts Telemetry.

CHAPTER 2.
LITERATURE REVIEW/BACKGROUND STUDY

2.1 Existing solutions

Content moderation systems have been explored across multiple technical paradigms:

  1. Rule-Based Systems: String-matching against static profanity lists. Fast (O(1)), but brittle against typos/slang and prone to false positives on substrings (the "Scunthorpe problem").
  2. Commercial SaaS APIs (Perspective API, Content Moderator): Pre-trained on large proprietary corpora. Highly accurate, but closed-source, recurring per-call costs, and lack domain policy customization.
  3. Generative LLM Assistants (ChatGPT, Claude): Fluent zero-shot comprehension, but prohibitive inference latency (1.5s–3s per comment) and high computational cost for high-volume streams.
  4. Isolated Academic Classifiers: Standalone Python research scripts with high reproducibility, but disconnected from production REST APIs, persistence databases, and administrative review workflows.

2.2 Literature and Research Trend Analysis

  1. N-Gram Baselines to Sequential Neural Models: Joachims (1998) established SVMs with TF-IDF for surface-level keywords. Kim (2014) applied 1D Convolutional Neural Networks (Conv1D) to extract localized n-gram features invariant to position.
  2. Recurrent Architectures & Vanishing Gradient Resolution: Hochreiter & Schmidhuber (1997) introduced LSTM gating mechanisms, and Graves et al. (2005) introduced Bidirectional LSTMs (BiLSTM) to capture preceding and succeeding semantic contexts. Zhou et al. (2016) showed that cascading CNN feature extraction with BiLSTM sequential modeling yields superior text classification.
  3. Multi-Label Classification & Imbalance Grounding: Tsoumakas & Katakis (2007) established that toxic discourse is inherently multi-label. Modeling each label independently with Sigmoid heads and weighted binary cross-entropy mathematically resolves severe class imbalance.

2.3 Review Summary & 2.4 Goals/Objectives

Existing solutions leave a gap between brittle static blocklists and high-latency LLMs. ToxicGuard AI establishes seven engineering objectives: (1) Automated NLP slang normalization (50+ terms); (2) Multi-label DL classification with 6 independent Sigmoid heads; (3) Weighted loss function engineering; (4) Sub-100ms inference latency on CPUs; (5) Asynchronous FastAPI backend; (6) Cryptographic JWT security & RBAC; and (7) Deterministic three-tier governance (Approved <0.40, Flagged 0.40–0.75, Blocked ≥0.75).

CHAPTER 3.
DESIGN FLOW/PROCESS

3.1 Evaluation & Selection of Specifications/Features

The system is decomposed into four modular subsystems: (1) NLP Subsystem: Regex sanitization, SLANG_MAP lookup, negation-preserving stopword filter, WordNet lemmatizer, sequence padding; (2) Inference Subsystem: Hybrid CNN + BiLSTM model with calibrated probability thresholding; (3) Backend & Persistence: FastAPI ASGI service, SQLAlchemy ORM, SQLite database, seed generator; (4) Frontend SPA: React 19, Tailwind CSS v4, Social Feed, Live Check, and Recharts Telemetry.

3.2 Design Constraints & 3.3 Analysis of Features

Core constraints navigated include: sub-100ms inference ceiling for real-time feed responsiveness, severe class imbalance (<1% threats), multi-label independence, zero native binary dependencies (pure Python/Keras), and role-based credential security. To satisfy these constraints, we finalized: (a) Upstream algorithmic slang expansion before tokenization; (b) Hybrid 1D CNN + BiLSTM for fast CPU inference (<40ms); and (c) Three-tier policy thresholding ($P_{max} < 0.40$ Approved, $0.40 \le P_{max} < 0.75$ Flagged, $P_{max} \ge 0.75$ Blocked).

3.5 Design selection

Table 3.1 provides the technical justification for the architectural selections made in ToxicGuard AI versus alternative approaches.

CHAPTER 4.
RESULTS ANALYSIS AND VALIDATION

4.1 Implementation of solution

4.1.1 Application Interface and Navigation

ToxicGuard AI provides an intuitive web interface built with Tailwind CSS v4 featuring four core navigation views: (1) Community Social Feed: Interactive post feed with real-time AI scoring, displaying Approved badges, Under Review banners, or Blocked tags; (2) Live Toxicity Analyzer: Diagnostic console displaying animated multi-category probability bars and latency meters; (3) Admin Moderation Queue: Administrative panel for reviewing flagged posts with 1-click Approve/Delete actions; (4) Model Performance Hub: Benchmark comparison dashboard presenting Macro F1, ROC-AUC, and Accuracy metrics.

4.1.2 NLP Text Preprocessing and Normalization Pipeline

Raw text undergoes four deterministic transformations: (1) Sanitization: Regex stripping of HTML, URLs (http\S+|www\S+), and letter elongations ("soooo goooood" → "soo good"); (2) Slang Expansion: Normalization of 50+ toxic acronyms via lookup dictionary ("wtf" → "what the fuck", "kys" → "kill yourself"); (3) Negation-Preserving Filter: Stripping stopwords while retaining negation tokens ("not", "never", "without") to prevent sentiment inversion; (4) Tokenization & Lemmatization: NLTK WordNet lemmatization and sequence padding to fixed length L = 50.

4.1.3 Deep Learning Multi-Label Model Architectures

Unlike single-label Softmax models, each category is modeled as an independent binary event via 6 Sigmoid activation units. The production Hybrid CNN + BiLSTM architecture operates as follows:

E = Embedding(X) ∈ ℜN × 50 × 64  •  C = ReLU(Conv1D(E))  •  Ht = [ h⃗t  ‖  h⃖t ] ∈ ℜ64
σ(zk) = 1 / (1 + e−zk),   k ∈ {1, 2, ..., 6}

4.1.4 Class Imbalance Mitigation and Loss Function Engineering

To prevent model collapse on rare minority classes (*Threat* < 1%), we implement Weighted Binary Cross-Entropy Loss:

ℒ = − (1/N) ∑i=1..N ∑k=1..6 [ wk yik log(pik) + (1 − yik) log(1 − pik) ]   where   wk = Nnegative, k / Npositive, k

4.1.5 Asynchronous High-Throughput FastAPI REST Backend

Built with FastAPI and Uvicorn ASGI, featuring non-blocking asynchronous request handlers, automated Pydantic schema validation (PredictRequest, CommentCreate), and interactive OpenAPI Swagger documentation at /docs.

4.1.6 Database Persistence Layer & 4.1.7 JWT Security

Persistence is managed via SQLAlchemy ORM backed by SQLite (toxic_moderation.db), normalizing User, Comment, and ModerationLog entities. Passwords are encrypted with salted bcrypt hashing, and requests are authenticated via HS256-signed Bearer JWT tokens valid for 24 hours with role claims (user / admin).

4.1.8 Interactive Analytics Telemetry

The administrative analytics engine aggregates 350+ seeded historical comments into 14-day area trends, category breakdown charts, and confidence distribution histograms rendered with Recharts.

CHAPTER 5.
CONCLUSION AND FUTURE WORK

5.1 Conclusion

The ToxicGuard AI capstone project successfully conceptualized, engineered, and validated an integrated content moderation platform combining NLP text normalization, multi-label Deep Learning classification, high-throughput asynchronous REST APIs, and responsive data analytics. Key achievements include: (1) Robust NLP text normalization expanding 50+ toxic internet slang terms; (2) Multi-label benchmarking of six model architectures with weighted loss optimization; (3) Three-tier calibrated policy engine; (4) Asynchronous FastAPI backend with JWT authorization and SQLite persistence; (5) Modern React 19 interface with Recharts telemetry; and (6) 100% test pass rate across 11 automated test suites with sub-100ms inference.

5.2 Future Work

Future engineering avenues include: (1) Transformer Fine-Tuning: Integrating quantized DistilBERT/RoBERTa for enhanced attention; (2) Multilingual Moderation: Expanding slang mappings and tokenizers to cross-lingual embeddings (XLM-RoBERTa); (3) Conversational Threading: Analyzing multi-turn conversational dialog trees to detect subtle sarcasm; (4) Bayesian Reputation Scoring: Dynamically adjusting thresholds based on user history; and (5) Federated Learning: Enabling privacy-preserving collaborative model updates.
